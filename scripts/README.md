# Scripts

All analysis code, split by language. Nothing here is a self-contained
pipeline you run top-to-bottom — each script is one analysis or one figure
panel, invoked directly with CLI args (see `../FIGURES.md` for the panel→script
map and `../RUN.md` for the dependency-ordered run sequence).

```
scripts/
└── python/      # the revision analyses — see python/README.md
    └── chromatin_surrogate/   # standalone Fig 5C sub-pipeline, own README + env
```

## Scope

- **Python** (`python/`) — everything added or reworked for the revision:
  integration QC, trajectory/CellRank, regulons/decoupleR, CNV concordance,
  doublet robustness, and all of the Fig 2–6 + supplementary plotters.
- The *original* manuscript pipeline steps never ported to Python (Cell Ranger /
  Seurat clustering, the inferCNV run, GSEA/fgsea) are **not included** in this
  Python release; their tool versions are recorded in `../config/params.yaml`
  (`versions:`) and their outputs are provided as the deposited AnnData objects
  (see `../data/objects/MANIFEST.md`).

## Conventions

- **Parameters.** No script hardcodes a threshold, seed, or software version.
  Everything lives in `../config/params.yaml`; Python scripts take the
  relevant values as CLI flags (defaults documented per-script `--help`). If
  you add a new magic number, put it in `params.yaml` first.
- **Data objects.** Scripts take data paths as arguments (`--h5ad`, etc.) —
  none are hardcoded. See `../data/objects/MANIFEST.md` for which of the
  three canonical AnnData objects a given analysis needs.
- **Don't hand-edit outputs.** Figures and derived tables are regenerated by
  re-running the script, not edited in place (see `../figures/README.md`).

## Adding a script

1. Write it to read its inputs via CLI args (no hardcoded paths).
2. If it's Python and needs a plotting/sort-key helper, check `python/_utils.py`
   first — add to it instead of duplicating.
3. Register it in `../FIGURES.md` (which panel/table it produces) and, if it
   introduces a new pipeline dependency, in `../RUN.md` (which stage it
   belongs to).
4. If it reads a new parameter, add it to `../config/params.yaml` rather than
   hardcoding.
